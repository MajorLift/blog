title: "The Placebo Arm Never Got to Run"

*I tried to run the control condition the last essay said oversight research was missing. Fifty-three of fifty-four runs passed with nobody watching, which left an interrupt nothing to improve, and the reason the floor sat that high is the finding.*

The previous essay ended on a charge. Every study that finds human feedback improves an automated process measures against the same baseline, no feedback, and that baseline cannot separate the value of the overseer's judgment from the value of being interrupted at all. Oversight research has never run its placebo arm. A charge like that obligates its author, so I tried to run the arm myself, starting where the design forces anyone to start. Before measuring what an interrupt adds, an experiment needs the run-to-run variance of uninterrupted work, and that is the control condition. So I ran two pilots with an AI model as the subject, no interrupts of any kind, and every run graded by a deterministic test suite that never learns which run produced which output.

The first pilot used ten self-contained programming tasks, three identical runs each, thirty runs in total. Twenty-nine passed. The one disagreement between identical runs came on a task where two runs guarded an empty-string case and the third did not. Disagreement of exactly this kind is what the eventual experiment would feed on, since an interrupt can only show its effect against run-to-run variance, and thirty runs produced a single bit of variance.

That looked like a task-difficulty problem, so the second pilot was built to remove the excuse. It used eight debug-from-spec tasks, each seeded with a defect planted to survive the visible tests, so that the model had to reason from the specification rather than chase a failing test. The planted defects were not cosmetic: a non-terminating loop, a cache that evicted the wrong entry, input mutated through shared nested references, an error case swallowed silently, a complexity bound violated while every visible test stayed green. All twenty-four runs passed, with zero run-to-run disagreement.

Combined, fifty-three of fifty-four runs passed across eighteen tasks, with one disagreement in total. A control arm exists to establish the floor an intervention would have to lift, and this floor sat at the ceiling, leaving an interrupt, whether judgment-bearing or random, nothing to improve.

Two further findings are mechanical, but they price any future attempt. First, repeated runs of a fixed task carry almost no information. Nearly every second and third run merely confirmed what the first had established, so statistical power has to come from task count, not repetition, and a budget of thirty runs buys ten tasks of evidence rather than thirty. Second, difficulty did not rise with defect subtlety. The eviction-order error and the violated complexity bound were meant to be the hard tier and fell exactly as reliably as everything else. Whatever gradient separates tasks a model completes cold from tasks it cannot, subtlety of the planted defect does not climb it.

The third finding was not in the plan. The single-function tasks completed in two tool calls. An interrupt injected into an in-flight search needs an in-flight phase to exist, some stretch of trajectory where the search is still open and a perturbation could push it somewhere else. A task that finishes in two steps has no middle to interrupt. The manipulation I was piloting toward had no surface to land on, not because interrupts do nothing but because these tasks contain no interval in which anything is still undecided.

Set the three findings side by side and they point at one structural fact. A machine can only score a task whose success criterion was written down in advance. That is what a test suite is, a criterion enumerated before the work begins, executable without judgment precisely because every case it covers was foreseen. But a criterion that can be written down in advance marks exactly the situations where oversight was already predicted to be absorbable, where a contract, a test, or a gate can encode what "done" means and enforcement can migrate into machinery. So the experiment is easiest to run precisely where it is least informative. The tasks that can be graded blind, cheaply, and deterministically are the tasks on which the case for oversight was already conceded, while the situations where oversight should matter, the ones whose criterion is not enumerable beforehand, are the ones no test suite can score. A criterion that cannot be enumerated in advance cannot be machine-scored without a human judge, and a criterion that can be enumerated in advance never needed a human overseer. The measurement problem and the oversight problem meet in the same place, at whoever holds the criterion.

The scope of this evidence should be stated plainly. It covers eighteen tasks, one model tier, and one task family, short self-contained programming problems of the kind benchmarks are made of. Nothing in fifty-four runs rules out interrupts mattering on long tasks, on weaker models, or on work whose requirements shift midway. The pilots establish only that this task family cannot carry the experiment, because its floor leaves no headroom and its trajectories no middle.

An argument in this position sits one step from the oldest failure in theory-building, a hypothesis that conveniently explains why it cannot be tested. The predecessor essay claimed the placebo arm was missing. This essay reports that the cheap version of the arm measures nothing, and the theory itself supplies a flattering reason why. Stopping there would convert the theory into an alibi. So instead of the excuse, here is the price. The instrument that would settle the question is a pool of long-horizon tasks in real repositories, with requirements not fully specified in advance, run with and without interrupts, and with outcomes scored by human judges under a protocol where the judge never sees the intervener's reasoning, only the artifact. Blinding survives, but the grader becomes a person, and a person per outcome is the cost that enumerable-criterion designs exist to avoid. No existing benchmark supplies this instrument, because benchmarks are built around exactly the pre-written criteria that make them cheap to run. It is worth building anyway, and not as a rig for this one hypothesis. Whoever wants to know what oversight contributes, on any account of what that contribution is, needs the same pool of under-specified tasks and the same blinded judges, so the instrument is general infrastructure for a question the field keeps answering with the wrong denominator. The pilots do not show that the question is unanswerable. They show that answering it costs a human judge per outcome, and that every design which avoids the judge is measuring the tasks that never needed the human. Measurement here is expensive. It was never impossible, and the distance between those two words is the distance between a research program and an alibi.
